How to set a hard cost ceiling on an LLM agent

A retry loop does not announce itself. It just keeps calling. The invoice arrives at the end of the month, or the card gets declined at 3am. Here is the mechanism that stops it.

The three limits that matter

LimitWhat it stopsWhy one limit is not enough
maxCostPerRequestOne oversized context or poisoned promptA single request can be huge without being a loop
maxCostPerHourRetry storms, non-converging loopsDaily limits let a loop burn everything in 20 minutes
maxCostPerDayThe number you actually signed off onA monthly limit is too coarse to react

Why the check must happen before the call

Post-hoc monitoring tells you what happened. It does not stop it. A budget guard has to estimate the cost of the next request and refuse to send it — otherwise the provider has already billed you by the time you find out.

if (spentHour + estimatedCost > maxCostPerHour) {
  throw new BudgetExceededError(...);
}
await fetch(provider, payload);   // never reached

Estimating cost before you know the response

You cannot know output tokens in advance. Input tokens are exact (count them); output is usually 0.3–1.5× input for chat workloads. Overestimating fails early (safe). Underestimating fails late (expensive).

A complete implementation

tokensave implements exactly this — three limits, checked pre-call, plus a savedByCeiling counter showing what it prevented.

const client = new TokenSaver({
  apiKey: process.env.OPENAI_API_KEY,
  maxCostPerRequest: 0.50,
  maxCostPerHour: 5,
  maxCostPerDay: 25,
});
